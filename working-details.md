# Working Details

## API Keys Usage

`process-tutorial-job` uses two different AI services for two different jobs:

| Step | Service | Why |
|---|---|---|
| **Script generation** — captions, narration text, image prompts per frame | **Claude** (`claude-haiku-4-5`) | Structured JSON output, better at writing simple clear language for IDD users, cheap + fast |
| **Image generation** — actual visuals per frame | **OpenAI DALL·E 3** | Claude can't generate images |
| **Audio narration** — MP3 per frame | **OpenAI TTS-1** | Claude can't generate audio |

### Where to get the keys

- **CLAUDE_API_KEY** — [console.anthropic.com](https://console.anthropic.com) → API Keys
- **OPENAI_API_KEY** — [platform.openai.com](https://platform.openai.com) → API Keys (requires billing enabled)

### Where to add them

Supabase dashboard → **Edge Functions** → **Manage secrets**

### Rough cost per tutorial (20s, 4 frames)

| Service | Cost |
|---|---|
| Claude script | ~$0.002 |
| DALL·E 3 images (4×) | ~$0.16 |
| TTS-1 audio (4 frames) | ~$0.001 |
| **Total** | **~$0.17 per tutorial** |

## Visual Style & Image Style (Create Tutorial)

Two independent style pickers in the Create Tutorial form. Both are injected into the AI prompt and influence what `image_prompt` Claude writes for each frame — which is then passed to DALL·E 3.

### Visual Style — art direction / rendering medium

| Option | What it tells the AI |
|---|---|
| **2D Animation** | flat vector illustration, bold outlines, bright colours, friendly characters |
| **3D Cartoon** | 3D Pixar-style render, vibrant colours, friendly cartoon characters |
| ~~Real Human~~ | photorealistic, real person demonstrating the action *(filtered out of the mobile picker)* |

### Image Style — composition complexity

| Option | What it tells the AI |
|---|---|
| **Simple & Bold** | high contrast, minimal detail, large clear shapes, uncluttered background |
| **Detailed** | realistic scene composition, environmental context, multiple elements |
| **Symbol-Based** | icon/pictogram style, AAC-compatible visual language (for users who rely on symbol communication systems) |

### Do different styles cost more?

No. Cost is driven by number of frames and which API is called — not by what the prompt describes. `gpt-image-1` charges per image regardless of prompt content. Visual Style and Image Style only add ~15–20 words to the system prompt, negligible token cost.

## IMAGE_TIMEOUT_MS — the 40,000ms image timeout

Defined in `process-tutorial-job` as `IMAGE_TIMEOUT_MS = 40_000` (40 seconds).

Each frame's image is generated by calling `gpt-image-1`. That call is wrapped in a `withTimeout()` helper that races the API call against a 40-second timer. If OpenAI hasn't responded within 40 seconds for a given frame, the timeout fires, throws an error, and the whole job fails — the tutorial status is set to `rejected` with the error message shown to the guardian, e.g. `"Timeout after 40000ms: image frame 3"`.

### Why 40 seconds?

Supabase Edge Functions have a wall-clock execution limit (60s on free tier, 150s on paid). With 3 frames, each potentially hitting 40s, plus the Claude script call and TTS audio generation, the total job must stay inside that limit. 40s per image is generous enough to handle slow OpenAI responses while still leaving headroom for the rest of the job.

### What to tell guardians

This is a transient OpenAI latency issue — nothing wrong with the tutorial content. Tapping **Resubmit for Review** queues a fresh generation job and most retries succeed.

## DB Webhook — `on_tutorial_job_insert`

### Why it's needed

When a guardian submits a tutorial form, the `create-tutorial` edge function inserts a row into `tutorial_jobs` and returns immediately — the app doesn't hang waiting for AI generation (which takes 30–60 seconds).

The webhook watches `tutorial_jobs` for new `INSERT` events and automatically fires `process-tutorial-job`, which does the heavy work:
- Calls Claude for the script
- Calls DALL·E 3 for each image
- Calls OpenAI TTS for each audio file
- Updates the tutorial status to `preview`

Without the webhook, `process-tutorial-job` would never get called and tutorials would stay stuck at `generating` forever. It's the async job queue — `create-tutorial` queues the job, the webhook kicks off the worker.

### Setup

Supabase dashboard → **Database → Webhooks → Create a new hook**

| Field | Value |
|---|---|
| Name | `on_tutorial_job_insert` |
| Table | `tutorial_jobs` |
| Events | `INSERT` |
| Type | Supabase Edge Functions |
| Edge Function | `process-tutorial-job` |
